<Fragment>Neural network kernels for <em>Ambiq silicon.</em></Fragment>
<Fragment slot="summary">
heliaCORE is Ambiq’s neural network kernel library for Apollo devices. Built on
Arm CMSIS-NN, it combines expanded operator coverage, quantized and floating-point
computation, and optimized Cortex-M DSP and Helium paths to power inference on
Ambiq silicon.

<div class="section-heading">
<h2>Optimized computation throughout your model</h2>
<p>Production models do more than convolution and matrix multiplication. They
also move tensors, combine results, and maintain state. heliaCORE gives model
integrations optimized library kernels for more of these operations, including
the work between convolution and dense layers.</p>
<p>For most applications, start with <a class="inline-link" href="#inference">heliaAOT or heliaRT</a>,
which use heliaCORE to execute supported model operations on Ambiq devices.
heliaAOT is the recommended starting point for latency, power, and memory
efficiency. Direct kernel integration is available for custom runtimes and
firmware that need control over individual operations.</p>
</div>
</Band>

<Band density="compact">
<div class="section-heading">
<div>
<p class="eyebrow">Operator coverage</p>
<h2>Coverage across production model graphs</h2>
</div>
<p>Alongside the convolution, dense, and other kernels inherited from Arm CMSIS-NN,
heliaCORE adds extensive support for tensor indexing, reductions, comparisons,
broadcast math, and recurrent networks. This extends kernel coverage to more of
the operations that make up a complete model. Your inference runtime or compiler
also determines which model operations it can map to these kernels.</p>
</div>
<div class="family-grid">
<article>
<h3>Tensor indexing and updates</h3>
<p>Gather, GatherND, ScatterND, Tile, Select, ReverseSequence, and DynamicUpdateSlice extend the graph operations available to your model.</p>
</article>
<article>
<h3>Reductions and comparisons</h3>
<p>Reduce sum, minimum and maximum, ArgMin, ArgMax, and comparison kernels cover decisions and aggregation within the graph.</p>
</article>
<article>
<h3>More floating-point operations</h3>
<p>FP16 and FP32 additions include broadcast add, subtract and multiply, gather, and reductions, alongside convolution and dense layers.</p>
</article>
<article>
<h3>Extended recurrent support</h3>
<p>FP16 and FP32 GRU kernels expand recurrent model support beyond the inherited LSTM and SVDF implementations.</p>
</article>
</div>

<Band tone="muted" density="compact">
<div class="section-heading">
<div>
<p class="eyebrow">Cortex-M acceleration</p>
<h2>Put DSP and Helium to work</h2>
</div>
<p>Use the compute features already in the processor. heliaCORE selects implementations
from the target's compiler flags, with specialized paths for supported kernels
and portable C implementations where the selected API provides one.</p>
</div>
<div class="acceleration-grid">
<article>
<p class="feature-tag">DSP extensions</p>
<h3>Packed integer computation</h3>
<p>DSP instructions process packed integer values and accelerate multiply-accumulate
operations used by quantized kernels.</p>
</article>
<article>
<p class="feature-tag">Helium / MVE</p>
<h3>Vectorized neural network math</h3>
<p>Hand-tuned vector implementations accelerate integer and floating-point operations,
with predicated processing for the ends of tensors.</p>
</article>
<article>
<p class="feature-tag">Memory control</p>
<h3>Buffers owned by your firmware</h3>
<p>No dynamic allocation inside the library. Query scratch-buffer requirements
and supply the memory from your application's allocation strategy.</p>
</article>
</div>

Nothing selects the DSP or MVE kernels at run time. The path is fixed when the
library is compiled, by the architecture features the compiler reports for the
target core.

## The compiler decides, the headers follow

{/* Include/arm_nn_math_types.h:56-91: __ARM_FEATURE_DSP defines
     ARM_MATH_DSP, __ARM_FEATURE_MVE & 1 defines ARM_MATH_MVEI, and
     __ARM_FEATURE_MVE & 2 is the float-MVE case. README.md, "Operator
     support", states the same rule in prose. */}

`Include/arm_nn_math_types.h` reads the predefined macros the compiler sets
from `-mcpu` and the rest of the architecture flags:

| Compiler macro | Defines | Meaning for a kernel |
|---|---|---|
| `__ARM_FEATURE_DSP == 1` | `ARM_MATH_DSP` | The DSP-extension implementation is compiled. |
| `__ARM_FEATURE_MVE & 1` | `ARM_MATH_MVEI` | The integer MVE implementation is compiled. |
| `__ARM_FEATURE_MVE & 2` | float MVE available | The half-precision vector forms can be used. |
| neither | — | The scalar C implementation is compiled. |

The library sets no `-mcpu` of its own. It compiles with the flags the
consuming target carries, which is why a prebuilt archive records the flags it
was built with and the CMake package refuses a mismatch.

## What CMake decides

{/* cmake/ns_cmsis_nn.cmake: the four public entry points at lines 14-36, the
     23 group ids at lines 77-100, and the DTYPES filter at lines 43-46.
     CMakeLists.txt:22-23 and 51-74 are the options that drive them. */}

`cmake/ns_cmsis_nn.cmake` is the single source of truth for the source layout,
and the standalone CMake build, the Zephyr module and the NSX module all go
through it. It decides three things:

- **Which operator groups are compiled.** There are 23 group ids, each with an
  explicit subdirectory under `Source/` and an explicit set of patterns. Each
  has a CMake option, on by default, so a project can drop the families it does
  not use.
- **Which data types are compiled.** `DTYPES` filters source files by the tag
  in their name; see [Data types and quantization](../data-types/).
- **Whether floating point is compiled at all.** `ARM_NN_ENABLE_F32` and
  `ARM_NN_ENABLE_F16` are off by default.

Because all four delivery paths read the same module, a Zephyr build and a
CMSIS-Pack build select the same sources for the same options. The
`ssot-contract` workflow is what keeps that true; see
[CI matrix](../../contributing/ci-matrix/).

## What a consumer should check

- The `-mcpu` and float ABI flags on the target that links the library, since
  those are what set the feature macros above.
- Whether the float options are on, when a model needs `f16` or `f32` kernels.
- The configure-time messages from the `find_package` package, which report
  the compiler ID and CPU it validated.

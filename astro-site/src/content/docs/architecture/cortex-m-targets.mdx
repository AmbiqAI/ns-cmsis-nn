heliaCORE builds for Apollo-class Cortex-M cores. Which kernels a build gets is
decided by the architecture features the compiler reports for the core, not by
a device name in the library.

## Core classes and the path they get

{/* README.md, "Operator support": the backend table and the sentence above
     it that optimizations are picked at compile time from the architecture
     features the compiler reports. */}

| Core class | Path used | Notes |
|---|---|---|
| Cortex-M0, M3 | Pure C | No DSP extension and no MVE; the baseline path is always available. |
| Cortex-M4, M7, M33 | DSP | Uses the SIMD intrinsics of the DSP extension. |
| Cortex-M55, M85 | MVE | Uses Arm Helium, the M-Profile Vector Extension. |

Apollo510 is the Cortex-M55 board the published cycle counts were measured on;
see [Kernel benchmarks](../../performance/kernel-benchmarks/).

## What a release builds for

{/* The three CPU names are the build matrix in
     .github/workflows/staticlib-dryrun.yml and pack-dryrun.yml
     (`target_cpu: [cortex-m0, cortex-m4, cortex-m55]`); the toolchain names
     are the artifact names described in getting-started/index.mdx. */}

Every release builds static libraries for three CPU names, each one with each
of the packaged toolchains:

| Artifact CPU | Covers | Float ABI |
|---|---|---|
| `cortex-m0` | Cortex-M0 and M0+ baseline Apollo targets | Soft float |
| `cortex-m4` | Cortex-M4 targets | FPv4 SP-D16, hard float |
| `cortex-m55` | Cortex-M55 targets with MVE | Hard float |

The toolchain name in an artifact is `gcc`, `atfe`, or `armclang`. A prebuilt
archive is compiled with one set of CPU flags and one compiler, so the CMake
package checks the consuming project's compiler ID and `-mcpu` at configure
time rather than letting a mismatched archive reach the linker. Source
integration paths compile the kernels with the project's own toolchain
instead; see [Toolchains](../../getting-started/toolchains/).

For the exact compiler versions each CI job uses, and which cores it executes
on rather than only builds for, see
[CI matrix](../../contributing/ci-matrix/).

## Choosing a target

- Build from source when the project needs local flags, a qualification
  record, or a compiler version that differs from the release.
- Take the prebuilt archive whose CPU and toolchain match the project, when the
  project already uses one of the three.
- Expect the scalar C path on anything without the DSP extension. It is not a
  fallback that has to be enabled; it is what the kernels compile to when the
  compiler reports no acceleration feature.

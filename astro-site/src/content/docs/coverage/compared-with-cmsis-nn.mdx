heliaCORE was forked from [Arm CMSIS-NN](https://github.com/ARM-software/CMSIS-NN)
and is maintained as an Ambiq silicon-focused kernel library. This page states
what that means for an integration, and nothing beyond what the repository
says. It makes no performance comparison against upstream; the measurements
this site publishes compare heliaCORE's own paths on one board, on
[Kernel benchmarks](../../performance/kernel-benchmarks/).

## What stays the same

- The inherited CMSIS-NN-style `arm_*` entry points, signatures, and behavior
  where those APIs are supported.
- Doxygen comments for inherited APIs, kept close to upstream when possible.
- License notices and attribution for inherited Arm CMSIS-NN sources: upstream
  files stay under Apache-2.0 and carry both copyright notices.

The library builds as `libcmsis-nn.a` and exposes a `cmsis-nn` CMake alias, so
a project that already links CMSIS-NN, including TFLM's integration, links this
one the same way.

## What Ambiq added

- Ambiq-specific kernels, variants, and Apollo optimizations for HELIA
  workflows. A kernel that exists here and not upstream, `arm_gather_s8` among
  them, is intentional.
- Operator families beyond the inherited set. The build's source of truth,
  `cmake/ns_cmsis_nn.cmake`, carries 23 operator group ids, including gather,
  comparison, strided slice, tile, broadcast, scatter, select, reverse
  sequence, and dynamic update slice.
- The experimental inherited `float32` and `float16` APIs, off by default
  behind `ARM_NN_ENABLE_F32` and `ARM_NN_ENABLE_F16`, plus Ambiq float variants
  of elementwise, reduction, activation and convolution kernels.
- The delivery and validation surface: per-CPU static libraries and SDK
  tarballs, a CMSIS-Pack, a Zephyr module, a neuralSPOT-X integration, and
  `find_package` checks on compiler ID and CPU flags.

Because a project can be built against either library, `Include/arm_nn_types.h`
defines a macro a caller can test at compile time before calling an Ambiq-only
kernel.

## Which one to use

Upstream Arm CMSIS-NN is the right choice for vendor-neutral Cortex-M work. Use
heliaCORE when you are building HELIA AI workflows for Ambiq silicon and need
Apollo-tuned kernels or Ambiq-specific operator coverage.

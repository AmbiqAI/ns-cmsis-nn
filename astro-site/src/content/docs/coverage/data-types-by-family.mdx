Every public kernel carries its data types in its name, so counting the
declarations in the public headers answers what each operator family supports.
The table below is generated at build time from the public headers
(<code>{coverage.headers.join(', ')}</code>): {coverage.totals.functions} declared functions, all of which fall
into one of the {coverage.families.length} API families.

A function is counted once in every column whose tag appears in its name, so
`arm_elementwise_mul_s16_s8`, which takes int16 inputs and writes int8, is
counted under both `s16` and `s8`. The **Functions** column counts each
function once.

## How to read it

- **`s8`, `s16`, `s4`** are the quantized kernels. `s4` is a weight-only tag: it
  appears on kernels that take int4 weights with int8 activations.
- **`s32` and `s64`** are accumulator and index widths rather than a model's
  activation type.
- **`q7` and `q15`** are the inherited CMSIS-NN names for the older fixed-point
  kernels.
- **`f16` and `f32`** are compiled only when `ARM_NN_ENABLE_F16` or
  `ARM_NN_ENABLE_F32` is on. Their declarations are in the header either way,
  which is why they are counted here.

A count is not a promise that every shape and every acceleration path is
covered for that type. Check the [API reference](../../reference/) for the
kernel you intend to call.

For what the tags mean in a build, see
[Data types and quantization](../../architecture/data-types/).

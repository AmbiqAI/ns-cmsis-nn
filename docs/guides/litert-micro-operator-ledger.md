# LiteRT Micro operator ledger

**2026-11-27.** Which LiteRT Micro operators can an embedded float model map to heliaCORE, and which kernels should we add next? This inventory covers every distinct builtin registered by the pinned upstream Micro resolver. The planning target is FP32 parity plus useful native FP16 extensions. It tracks public kernel availability on CORE main. The existing cross-team tracker records AOT lowering, RT adoption, qualification and release milestones. [Micro resolver](https://github.com/tensorflow/tflite-micro/blob/8efacb0447638d7a29bae947526d27535a4bd1e2/tensorflow/lite/micro/micro_mutable_op_resolver.h) · [CORE float declarations](https://github.com/AmbiqAI/ns-cmsis-nn/blob/5f8f478b57c13723bd8e083fb6f88608c04b3e27/Include/arm_nnfunctions_flt.h) · [Integer and Boolean declarations](https://github.com/AmbiqAI/ns-cmsis-nn/blob/5f8f478b57c13723bd8e083fb6f88608c04b3e27/Include/arm_nnfunctions.h) · [Cross-team tracker #523](https://github.com/AmbiqAI/ns-cmsis-nn/issues/523)

For FP16, state whether the oracle is native-half arithmetic or FP32 evaluation rounded to half. A targeted kernel improvement can ship with other kernels in the same release.

## Evidence from exported models

- **HELIA zoo.** Parsed all 33 tracked `models/**/*.tflite` files across 14 model families, verified each LFS object against its Git SHA-256 pointer and inspected all subgraphs. The 1,007 operator instances span 25 builtin names. Six files contain nodes with FP16 tensors and seven contain nodes with FP32 tensors. The float graphs exercise existing CORE families such as convolution, depthwise convolution, fully connected, pooling, mean and multiply. None exercises float bilinear resize, comparisons, SELECT_V2, L2 normalization or log-softmax. The matrix counts distinct families to avoid over-ranking a model with many precision variants. These counts measure graph presence. Latency requires a target measurement. [Pinned zoo models](https://github.com/AmbiqAI/helia-model-zoo/tree/de2a931b02b2f5ddaa91a9b729edc31bf683f1eb/models)
- **MediaPipe DeepLab v3, float32 v1.** Three FP32 bilinear nodes use aligned corners. The first expands 1×1×256 to 33×33×256, the second is an identity at 33×33×21, and the third scales 33×33×21 to 257×257×21. The final output alone occupies 5,548,116 bytes. Use small board-sized crops with the same geometry and odd channel count. Identity and singleton-source shortcuts are legitimate benchmark cases. Model SHA-256 begins `ff36e24d4054`. [Model file](https://storage.googleapis.com/mediapipe-models/image_segmenter/deeplab_v3/float32/1/deeplab_v3.tflite)
- **MediaPipe Selfie Segmenter, float16 v1.** Three half-pixel-center bilinear stages double the spatial size with 128, 24 and 16 channels. The activation tensors at all three resize nodes are **FP32**. A model’s weight-format label alone would give the wrong kernel priority. These external graphs demonstrate operator demand. Whole-model deployment also depends on memory, other operators and, for Selfie Segmenter, a custom operator. Model SHA-256 begins `191ac9529ae5`. [Model file](https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_segmenter/float16/1/selfie_segmenter.tflite)

| Runtime | 8 | Shape calculation, resource state or control flow belongs to AOT/RT. |
| **Total** | **100** | One row per distinct upstream builtin registration. |

The reference column identifies the portable Micro **value type relevant to this audit**. FP32 describes an upstream float path. Byte-copy rows use a storage-generic implementation. The CORE FP16 entries are a HELIA product capability and do not imply upstream native-half arithmetic. The inventory establishes named APIs and inspected source paths. Operator versions, full integer type-pair parity, rank, arbitrary broadcasting, optional parameters, numerical equivalence, optimized backends and installed consumer execution require separate qualification.

**Release boundary.** v7.48.0 was the latest published CORE at audit time. Broadcast squared difference, grouped FP16/FP32 convolution and float bilinear resize are on the audited main revision after that tag. Standalone TOPK_V2, RBF and packed trees in #918 are outside this upstream resolver. GELU, GRU, REDUCE_ANY, SCATTER_ND and REVERSE_SEQUENCE are also outside the denominator, regardless of HELIA support. The resolver additionally offers custom registrations including detection postprocessing, signal processing and Ethos-U. Track those by custom name and provider if a model calls for them. [v7.48.0 to audited main](https://github.com/AmbiqAI/ns-cmsis-nn/compare/v7.48.0...5f8f478b57c13723bd8e083fb6f88608c04b3e27) · [Resolver](https://github.com/tensorflow/tflite-micro/blob/8efacb0447638d7a29bae947526d27535a4bd1e2/tensorflow/lite/micro/micro_mutable_op_resolver.h)

## Beyond one builtin at a time

Keep a separate queue for fused LayerNorm/RMSNorm and attention if transformer or streaming models become a priority. They do not appear as builtin registrations here. Look for repeated decompositions such as mean → squared difference → mean → rsqrt → scale, or batch matmul → softmax → batch matmul. Record real tensor dimensions, consumer counts and peak live intermediate bytes. A fused kernel earns its place when a representative export shows a measurable cycles or RAM benefit. This audit establishes no such measurement.

## Refreshing the ledger

1. Pin the upstream and CORE revisions. Enumerate the distinct names passed to `AddBuiltin(BuiltinOperator_…)` in the standard Micro resolver. Count custom registrations separately. Compare that set with the first column below the **Builtin ledger** heading.
2. For each changed row, inspect the portable registration’s Prepare/Eval type dispatch and the CORE public declarations and implementation. Check activation modes and parameterized kernels before marking a gap. Verify each brace-expanded symbol and its enabled dtype. A proposed lowering stays **Lower** until its shape, exceptional-value and alias contracts are checked for the intended consumer.
3. For demand, read the actual FlatBuffer subgraphs and resolve each operator’s opcode index. Count by model family and inspect operator input/output tensor types. Keep external models separate from the zoo. Record the exact shape and options when a graph changes a priority.
4. When work starts, attach its CORE, tester and consumer issue or PR to the queue row. Move it from proposed to in review, merged on main, then released with a version. Record the qualifying geometry and board measurements in the focused issue. Use [#523](https://github.com/AmbiqAI/ns-cmsis-nn/issues/523) for cross-team adoption.

# CMSIS-DSP public symbol snapshot, for scripts/check_dsp_symbol_collisions.py.
#
# One `arm_*` symbol name per line, sorted. This is every function CMSIS-DSP
# declares in its public headers: Include/*.h (top-level, e.g. arm_math.h,
# arm_vec_math.h) plus Include/dsp/*.h (e.g. basic_math_functions.h,
# statistics_functions.h) -- i.e. `Include/` scanned recursively.
# CMSIS-DSP's PrivateInclude/ is a sibling of Include/, not a subdirectory
# of it, so this scope excludes it automatically; PrivateInclude/ is not a
# directory a consumer #includes, mirroring why this repo's own
# Include/Internal/ is excluded from the "ours" side of the check (see
# check_dsp_symbol_collisions.py's header comment for that reasoning).
#
# ns-cmsis-nn is public and helia-dsp (Ambiq's private vendored CMSIS-DSP
# fork) is private, so CI cannot fetch this live -- it must be checked in.
# See ns-cmsis-nn issue #282.
#
# Source: upstream https://github.com/ARM-software/CMSIS-DSP -- the public
# canonical source, refreshable without private-repo access. Cross-checked
# at generation time against AmbiqAI/helia-dsp's vendored copy: the two
# trees are NOT byte-identical (helia-dsp carries Ambiq patches to a few
# inline-function bodies in Include/dsp/none.h and Include/dsp/utils.h,
# plus a comment wording fix in Include/dsp/controller_functions.h --
# 3 of 49 files under Include/, none of it touching a declared symbol
# name), but extracting symbols from both trees with extract_symbols()
# produces the identical 780-name set either way. Either tree is therefore
# a valid refresh source; upstream is used here so refreshing this file
# never requires private-repo access.
#
# The refresh recipe below and the live check both call the SAME
# extract_symbols(), which is the point (one extraction rule, not two to
# keep in sync) -- but it cuts both ways: a refresh can track upstream's
# real additions and removals, but it is structurally incapable of
# surfacing a bug IN the extractor itself. That happened here: an earlier
# version of DECL_RE's capture class was lowercase-only and silently
# dropped every declaration with an uppercase letter after "arm_" (e.g.
# arm_biquad_cascade_df2T_f32, arm_circularRead_f32) -- 17 real,
# unconditional, non-static symbols, some ordinary extern declarations,
# some __STATIC_FORCEINLINE definitions (in scope either way, see
# check_dsp_symbol_collisions.py's "Matches ... declaration or
# definition" comment). Every one of the 17 was present in CMSIS-DSP back
# in 2022's v1.10.1 too (see the four-year diff below), so this was never
# a staleness problem a refresh could have caught -- re-extracting
# against today's ref reproduced the old, wrong 763 byte-for-byte right
# up until DECL_RE itself was fixed. A tool bug is a tool bug regardless
# of how current the input is; only re-deriving this file after a
# genuine extractor change (like this one) fixes it, not a routine
# refresh.
#
# Acknowledged limit -- the real staleness axis is helia-dsp, not upstream:
# the symbol-identity check above is a snapshot in time, and what actually
# links against ns-cmsis-nn in Ambiq products is helia-dsp, a fork Ambiq
# patches -- not upstream CMSIS-DSP. An Ambiq engineer adding a DSP-side
# helper directly to helia-dsp under an obvious bare name (e.g. a
# hypothetical arm_softmax_f32 added there without ever going upstream) is
# a substantially more likely event than ARM adding a new bare NN-style
# verb upstream, and this guard is structurally blind to it: nothing
# re-derives this file from helia-dsp, so a helia-dsp-only addition would
# not appear here until the next manual refresh, if ever. Refreshing from
# helia-dsp instead of upstream on a schedule would close this, but no
# such job exists today -- upstream's own track record is why: diffing
# upstream tag v1.10.1 (2022-07-05) against the ref below (2026-08-12, so
# just over four years) adds 202 symbols and removes 10, and NONE of the
# 202 additions collide with what ns-cmsis-nn ships publicly today
# (verified by re-running check_dsp_symbol_collisions.py's own
# extract_symbols() against a v1.10.1 checkout). That is a good track
# record for upstream -- but helia-dsp is the fork that actually matters
# here, this file cannot see it, and a clean upstream history says
# nothing about what an Ambiq engineer might add there directly.
#
# Generated from:
#   upstream ARM-software/CMSIS-DSP @ c0c8640de1a6e190c35535d7069594ceb5855161
#     (2026-08-12, "arm_pid_q31: document that the final conversion does
#     not saturate (#327)")
#   cross-checked against AmbiqAI/helia-dsp @ 07a11b73f1181201edcaee9c9453b51dfecf4dcc
#     (2026-08-06, "feat(release): prepare helia-dsp v1.0.0 foundation")
#
# Refresh (on helia-dsp releases, or roughly monthly -- CMSIS-DSP's public
# surface is stable, so drift risk is low):
#
#   git clone --depth 1 https://github.com/ARM-software/CMSIS-DSP.git /tmp/cmsis-dsp
#   cd <ns-cmsis-nn checkout>
#   python3 <<'PY'
#   import sys
#   sys.path.insert(0, "scripts")
#   from pathlib import Path
#   from check_dsp_symbol_collisions import extract_symbols
#   headers = sorted((Path("/tmp/cmsis-dsp") / "Include").rglob("*.h"))
#   names = sorted(extract_symbols(headers))
#   Path("scripts/data/cmsis_dsp_symbols.txt.new").write_text("\n".join(names) + "\n")
#   print(len(names), "symbols")
#   PY
#   diff scripts/data/cmsis_dsp_symbols.txt scripts/data/cmsis_dsp_symbols.txt.new
#
# Review the diff (expect only additions/removals from real CMSIS-DSP API
# changes), fold the new ref/date into the header above, replace this file
# with the .new one, and delete the .new file. A helia-dsp clone works
# identically -- point the rglob at <helia-dsp checkout>/Include instead.
#
# A refresh that ADDS a name your PR does not otherwise touch is routine
# (CMSIS-DSP grew its surface). A refresh that REMOVES a name deserves a
# second look -- confirm it is an intentional upstream removal, not a
# checkout mistake, before committing.
